## Commands

```bash
npm run dev     # dev server (Next 16 uses Turbopack by default — no --turbopack flag needed)
npm run build   # production build
npm start       # serve the production build
npm run lint    # bare `eslint` — no path args, config resolves the project
```

No test runner is configured. `npm run build` (which type-checks) plus `npm run lint` are the only verification gates.

## Stack

Next.js 16 App Router · React 19 · TypeScript (`strict`) · Tailwind CSS v4.

Tailwind v4 is configured entirely through PostCSS (`@tailwindcss/postcss`) and the `@theme inline` block in [app/globals.css](app/globals.css) — there is **no `tailwind.config`**. Add design tokens as CSS custom properties in that block, not in a JS config.

Import alias: `@/*` maps to the repo root (`@/lib/types`, `@/components/CardVaga`).

## Architecture

The app is a "portal de vagas" (job/internship board). The code is written in Portuguese — types, variables, and props use pt-BR domain terms (`vaga`, `empresa`, `modalidade`, `salario`, `listar`, `criar`). Keep new code in the same language.

### Fake API over localStorage

[lib/api.ts](lib/api.ts) is a generic, key-based stand-in for a backend: `listar<T>(chave)`, `salvarLista<T>`, `criar<T>`. It reads and writes `localStorage` and `listar` sleeps 700ms to simulate latency.

Two consequences that drive the whole component tree:

1. **Every consumer must be a Client Component.** `localStorage` does not exist during SSR, so any page or component that calls these helpers needs `"use client"`. This is why [app/page.tsx](app/page.tsx) is client-side despite being a plain listing page.
2. **Reads are slow and stack.** `criar` internally calls `listar`, so each write costs ~700ms. Seeding 20 records serially takes ~14s. Prefer `salvarLista` with a whole array over looping `criar` when writing in bulk.

`criar` assigns `id: Date.now()`, so ids are only unique because of the artificial delay — don't remove the delay without changing id generation.

### Seeding

[lib/vagas-seed.ts](lib/vagas-seed.ts) holds 20 `Omit<Vaga, "id">` records. [app/page.tsx](app/page.tsx) seeds them into the `"vagas"` localStorage key on first load when the list comes back empty. The effect is guarded by a `useRef` flag because React StrictMode double-invokes effects in dev — without it the seed runs twice. Reuse that guard pattern for any other write-on-mount effect.

To reset the data during development, clear the `"vagas"` key from localStorage and reload.

### Types

[lib/types.ts](lib/types.ts) is the single source of domain types. `Modalidade` is a string union (`"presencial" | "remoto" | "híbrido"`) — extend it there rather than widening to `string` at call sites.

### Next 16 route typing

Layouts and pages use the globally generated route types, e.g. `RootLayout({ children }: LayoutProps<"/">)` in [app/layout.tsx](app/layout.tsx). These come from `.next/dev/types/routes.d.ts` and are regenerated by `next dev`/`next build` — after adding a route, run the dev server or a build so `PageProps<"/your/route">` resolves.
